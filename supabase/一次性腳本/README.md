# 一次性腳本 — 跑過就不用再跑的

這裡放**已經解決掉某個具體問題**的查詢與修正腳本。

跟 `supabase/` 根目錄那幾支的差別：

| 位置 | 用途 | 什麼時候會再開 |
|---|---|---|
| `supabase/查-*.sql` | **常用的健檢** | 每個月對帳、或懷疑數字不對時 |
| `supabase/一次性腳本/` | 某天某個問題的診斷與修正 | 幾乎不會 —— 留著是為了「當初怎麼修的」 |

**為什麼不直接刪掉**

這些腳本是某幾筆資料**現況的唯一說明**。哪天有人問「B6 的押金為什麼記在 B5」、
「Max 那則評價的房源是誰指定的」，答案在這裡。git 歷史也查得到，
但要先知道去哪個 commit 翻才行。

## 跑之前

1. **先讀檔頭。** 每一支開頭都寫了當初的症狀與為什麼這樣修。
2. **`修-` 與 `清-` 開頭的會改資料。** 確認你要修的是同一個問題，
   不是「看起來很像」的另一個。
3. **`查-` 開頭的只讀**，隨便跑沒關係。

> ⚠ `修-押金移房-B6轉B5.sql` 這種綁定特定 id 的腳本，
> 在別的資料上跑會改到不相干的列。它們**不是通用工具**。
