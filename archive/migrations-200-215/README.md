## 為什麼搬走

`supabase/migrations/` 的用途是**「這一輪要貼進 SQL Editor 的東西」**。
20 支裡有 15 支早就跑過，真正要找的那幾支埋在中間。

★ 這次的門檻比以前低（以前是累積到 40 支才切）——
2026-09-05 使用者指定「只保留 5 支」。理由成立：
`deploy.ps1` 推完會列出「還沒跑的 migration」，
清單越短，真的有東西要跑時越不會被忽略。

## 這一批裡最值得回頭看的三支

- **203**：`bank_transactions.balance` 是推導值卻存成欄位，
  維護它的只有前端一段程式。改成觸發器維護的理由寫在檔頭 ——
  那條坑（「推導值存成欄位」）後來又踩到兩次。
- **208**：206 建表時漏了 `create policy`，而 Supabase 的
  `rls_auto_enable()` 會自動開 RLS —— 沒有 policy 等於全部擋掉，
  查詢**回成功、0 列**。六筆人事費前端一筆都讀不到，
  而畫面上只是一個很正常的「0 筆 $0」。
- **211**：`hk_day.rooms_override` 那一欄**線上根本不存在**
  （migration_60 寫了但沒生效）。前端做樂觀更新又沒接 error，
  所以三個月來使用者以為「系統會自己算回去」。
  一個靜默的讀 ＋ 一個靜默的寫 ＝ 一個不存在的功能。
