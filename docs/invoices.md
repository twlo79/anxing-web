# 發票備忘功能

> 目的:**提醒**該開票、**確認**已開票、**備忘**開票所需資訊。
> 系統不串接加值中心、不代開發票、不驗證金額 —— 發票由人員在財政部平台或加值中心人工開立,系統只負責提醒與記錄。

## 三個設計要點

### 1. 發票的單位是「月」,不是「期」

收款視窗的 `cadPeriods` 依 `cadence` 分組:月繳 1 期 = 1 個月,**年繳 1 期 = 12 個月**。
青宇是年繳,畫面上只會出現 1 個「期」,但他需要 **12 張發票、12 個號碼**。

資料層本來就是對的 —— `gen_contract_orders` 是**逐月** upsert `LT_{room}_{YYYYMM}`,不論 cadence 為何,
`orders` 永遠一個月一列。因此:

> **一列 order = 一張發票**

月繳契約看起來沒有差別(1 期就是 1 月);年繳的青宇則在該期區塊內展開 12 個月,各自一顆開票按鈕。
這與延展功能已採用的「期內以每月獨立顯示」是同一個模式。

### 2. 發票必須獨立成表,不能加在 `orders` 欄位上

`gen_contract_orders` 觸發器會覆寫 `imported_via='contract'` 且 `paid=false` 的列。

傑太日煙是**先開後收**,開票當下 `paid` 仍為 `false`。此時只要有人編輯契約(展延、改租金、調租期迄),
那一列 order 就會被 upsert 掉 —— **已開立的發票號碼會消失**。發票號碼是報稅憑證,必須放在觸發器碰不到的地方。

`invoices` 表的 `room` / `title` / `tax_id` 是**開立當下的快照**,兩個外鍵都用 `on delete set null`,
即使日後契約或訂單被刪除,發票記錄仍然自我完整。

### 3. 待開清單以「月份」為準,不是以「入帳」為準

青宇年繳,收款時 12 個月的 order 會**一次全部**標成 `paid=true`。
若清單只看「已入帳且未開票」,青宇的 12 個月會同時湧入,其他四家會被淹沒。

正確邏輯:

- 只列 `ym = 當月` 的
- 加上 `ym < 當月` 但仍未開票的 → **標紅**(與「跨月欠款」同一套邏輯)

這樣青宇每個月只出現一列,在 17 號提醒。

## 資料結構

### `contracts` 新增欄位

| 欄位 | 型別 | 說明 |
|---|---|---|
| `invoice_required` | boolean | 是否需要開票,預設 `false` |
| `invoice_day` | smallint | 每月開票日 1–31 |
| `invoice_after_paid` | boolean | `true` 需確認入帳後才可開;`false` 可先開後收 |
| `invoice_title` | text | 發票抬頭/公司名,留空則沿用 `tenant_name` |
| `invoice_tax_id` | text | 統一編號 8 碼 |
| `invoice_note` | text | 固定備註,例 `PO4701105619` |

### `invoices` 新表

| 欄位 | 型別 | 說明 |
|---|---|---|
| `id` | uuid | PK |
| `contract_id` | uuid | → `contracts`,`on delete set null` |
| `order_id` | uuid | → `orders`,`on delete set null` |
| `room` | text | 快照,not null |
| `ym` | text | `YYYYMM`,發票所屬月份 |
| `amount` | numeric | 參考金額,**不強制、不比對** |
| `invoice_no` | text | 發票號碼,2 碼英文 + 8 碼數字 |
| `invoice_date` | date | 開票日期 |
| `title` / `tax_id` | text | 開立當下的抬頭、統編快照 |
| `note` | text | 本期臨時備註 |
| `status` | text | `issued` / `voided` |
| `issued_by` | uuid | `auth.uid()` |
| `created_at` | timestamptz | |

**索引與限制**

- `invoices_contract_ym_uniq` — `(contract_id, ym) where status='issued'`,同契約同月份只能有一張已開立發票
- 用 partial index 而非 unique constraint,日後若要作廢重開,作廢的舊列可與新列並存,不必改結構
- `invoice_no` 格式檢查:`^[A-Z]{2}[0-9]{8}$`

**RLS** — 比照 `contracts`,開放 `housekeeper` / `manager` / `super_admin`。
開票操作發生在收款視窗內、管家會用到,故不收緊。若日後要限制為 manager 以上,把 policy 裡的 `housekeeper` 拿掉即可。

## 介面規劃

### A. 契約編輯視窗 —— 發票設定區塊

一個「需要開發票」勾選框,勾選後展開:開票日、**收費後開**(勾選框)、公司名、統編、固定備註。
每個契約設定一次,之後不需再動。

### B. 收款視窗表頭 —— 開票資訊

顯示公司名、統編、固定備註,供人員對照著去平台開立。

### C. 收款視窗各月 —— 開票按鈕

每個月一顆按鈕,三種狀態:

| 狀態 | 條件 | 呈現 |
|---|---|---|
| 可開立 | `invoice_after_paid` 且已入帳,或 `invoice_after_paid=false` | 「開發票」按鈕 |
| 等待入帳 | `invoice_after_paid` 但未入帳 | 按鈕鎖住,顯示「尚未入帳」 |
| 已開立 | 已有 `invoices` 記錄 | 顯示發票號碼與開票日 |

點「開發票」跳出小視窗,填**發票日期 + 發票號碼**(+ 本期臨時備註),儲存。
發票號碼輸入時自動轉大寫,儲存前驗格式;備註預設帶入契約的固定備註。
視窗上方顯示抬頭、統編與參考金額,方便對照。

已開立的月份顯示號碼與日期,右側有「改」可重開視窗修正打錯的號碼,
視窗內另有「刪除記錄」——**只刪系統裡的備忘記錄,不影響平台上已開立的發票**。
這不是作廢流程,單純是打錯字的補救。

### D. 契約頁主畫面 —— 本月待開發票

放在「跨月欠款」下方,同一套視覺語言(欠款用紅色,待開發票用琥珀色以資區別)。

- 排序:逾期優先 → 月份舊到新 → `invoice_day` 小到大
- 每列:開票日、房號、抬頭、月份、金額、狀態,「先開」與固定備註以標籤呈現
- **過了開票日仍未開立 → 標紅顯示「逾期」**
- 點列直接開啟該契約的收款視窗

**回溯窗口 `INVOICE_LOOKBACK = 2`** —— 清單只涵蓋本月與前 2 個月。
若不設限,功能上線當下會把每個契約自起始月以來的所有月份都列成逾期(可能數十筆),
變成純噪音而被忽略。兩個月足以抓到真正漏開的,又不會翻出不會補開的歷史。
要調整就改 `page.tsx` 裡這個常數。

> 這一區是整個功能的核心價值。只放在編輯視窗裡的話,要「已經想起來要開票」才會看到 ——
> 但真正會漏的情境是**壓根忘記那天要開票**。

## 明確不做的事

| 項目 | 決定 | 理由 |
|---|---|---|
| 串接加值中心自動開立 | ❌ | 人工開立即可,只需備忘 |
| 金額驗證 / 加費併入計算 | ❌ | 加費(`CFEE_`)由人員自行處理,系統不介入 |
| 發票號碼全域唯一檢查 | ❌ | 會在補登舊資料時卡住 |
| 作廢重開流程 | ❌ UI 不做 | `status` 欄位先保留,日後要補不需改結構 |

## 部署順序

⚠ **SQL 必須先跑,前端才能推。**

1. Supabase Dashboard → SQL Editor 執行 `migration_30_invoices.sql`
2. 確認第 5 節的驗證查詢回傳 5 列且數值正確
3. 本機 `npx tsc --noEmit` + `npm run build` 通過
4. `git push origin main`

若順序顛倒,`contracts` 缺少 `invoice_*` 欄位,契約頁查詢會回 400,整頁掛掉。
migration 最後已帶 `notify pgrst, 'reload schema';` —— 新增欄位後不重載,PostgREST 仍會回報欄位不存在。
