# 標案管理 — 爬蟲串接

ERP 這一頭已經做好了（`migration_179`）。這份是**爬蟲那一頭要加的東西**。

爬蟲：<https://github.com/twlo79/tender-scraper>

## 一、ERP 這邊要先設兩個環境變數

主機上 `/opt/anxing-web/.env.local`：

```
IMPORT_KEY=<自己想一組長字串>
SUPABASE_SERVICE_KEY=<Supabase → Settings → API → service_role>
```

★ 這兩個**可能已經有了** —— 現有六支 import 端點（清潔、房務、Airbnb…）用的是同一組。
先看一眼，有的話不用動：

```bash
grep -c 'IMPORT_KEY\|SUPABASE_SERVICE_KEY' /opt/anxing-web/.env.local
```

改過要重啟：`pm2 restart anxing`

## 二、爬蟲 repo 加兩個 Secret

GitHub → tender-scraper → Settings → Secrets and variables → Actions：

| 名稱 | 值 |
|---|---|
| `ANXING_URL` | `https://<你的網域>/api/import/tenders` |
| `ANXING_KEY` | 跟上面的 `IMPORT_KEY` 一模一樣 |

`.github/workflows/daily.yml` 的 `env:` 底下加這兩行：

```yaml
          ANXING_URL: ${{ secrets.ANXING_URL }}
          ANXING_KEY: ${{ secrets.ANXING_KEY }}
```

## 三、`scraper.py` 加這一段

**★★ 加在「決定要推播哪些」之後、「送 LINE」的前後都可以，但一定要用同一份 `notify` 清單。**

使用者選的是「只收有推播的」——
所以送進 ERP 的必須是**通過關鍵字／地區／日期篩選之後**的那些，
不是爬到的全部。

```python
import os, json, urllib.request

def push_to_anxing(notify_by_source):
    """
    把今天要推播的標案送一份到安幸 ERP 的標案追蹤器。

    notify_by_source: { 來源名稱: [ {title, date, url, agency}, ... ] }
                      —— 就是拿去組 LINE 訊息的那一份

    ★ 失敗不要讓整支腳本掛掉。LINE 推播是主要功能，
      ERP 只是多一個去處 —— 為了它而讓當天的通知發不出去是本末倒置。
    """
    url = os.environ.get("ANXING_URL")
    key = os.environ.get("ANXING_KEY")
    if not url or not key:
        print("  ↷ 沒設 ANXING_URL / ANXING_KEY，跳過 ERP 匯入")
        return

    records = []
    for source, items in notify_by_source.items():
        for it in items:
            records.append({
                "source": source,
                "title":  it.get("title", ""),
                "url":    it.get("url") or "",
                "agency": it.get("agency") or "",
                # ★ 這是**公告日期**，不是截標日期。ERP 那邊欄位叫 posted_on，
                #   而且畫面上會寫「公告 2026-08-26」——
                #   不寫那兩個字的話會被當成截標日期。
                "date":   it.get("date") or "",
            })

    if not records:
        print("  ↷ 今天沒有要推播的，不打 ERP")
        return

    req = urllib.request.Request(
        url,
        data=json.dumps({"records": records}).encode("utf-8"),
        headers={"content-type": "application/json", "x-import-key": key},
        method="POST",
    )
    try:
        with urllib.request.urlopen(req, timeout=30) as r:
            print("  ✅ ERP 匯入：", r.read().decode("utf-8"))
    except Exception as e:
        # ★ 印出來但不 raise —— 見上面的說明
        print("  ⚠ ERP 匯入失敗（不影響 LINE 推播）：", e)
```

呼叫的地方（`main()` 裡，送完 LINE 之後）：

```python
push_to_anxing(notify)      # notify 就是組 LINE 訊息用的那一份
```

## 四、驗一次

不用等到明天早上八點：

**GitHub → tender-scraper → Actions → 選那個 workflow → Run workflow**

跑完看 log 最後幾行：

```
✅ ERP 匯入： {"received": 3, "saved": 3, "skipped": 0, "run_at": "2026-08-28T..."}
```

然後開 ERP 的**標案管理 → 標案追蹤器**，那三筆要在裡面。

| 回傳欄位 | 意思 |
|---|---|
| `received` | 收到幾筆 |
| `saved` | 實際寫進去幾筆（重複的會走 update，一樣算在內） |
| `skipped` | ★ 被丟掉的：沒有來源或標題、或同一批裡重複 |

★ `skipped` 一直不是 0 的話要看一下 —— 那代表爬蟲送出來的資料有欄位是空的。

## 五、幾個之後會踩到的

**① 改了 `scraper.py` 的白名單，ERP 的數量會安靜地跟著變。**

篩選條件寫死在 `SOURCES` 裡，而 ERP 只收通過篩選的。
所以每一筆都記了 `run_at` —— 哪天覺得「怎麼變少了」，
用那一欄查得出是從哪一天開始的。

**② 爬蟲的去重是「標題」，而且每個來源只留 300 筆會輪替。**

輪替掉之後同一筆會再被推一次。ERP 的唯一索引
`(source, url, title)` 是最後一道防線 —— 重複的會走 update 而不是新增一筆。

**③ 郵局那一支所有筆的 `url` 都一樣。**

所以唯一鍵含 `title`。少了它那 83 筆會互相覆蓋，
而且是安靜的：沒有錯誤，只是清單很短。

**④ 截標日期爬蟲給不出來。**

`date` 是公告日期，兩者常差好幾週。截標日期在各網站的詳情頁裡，
九個網站格式都不同 —— 目前是**人工填**。

ERP 那邊有一張「截標日期未填」的統計卡在盯這件事，
而且加星建檔後畫面最上面會寫「還沒填：地址、截標日期」。
