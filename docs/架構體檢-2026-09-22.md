## 🔴 會出錯的資料（建議先修）

### 1. 十七個「多步驟寫入」沒有交易 —— 第二步失敗就留半套

前端沒有交易。這 17 個函式各自連續寫兩張以上的表，任一步失敗，前面已經寫進去的不會退回。`DeferralPanel` 那次（migration_228）就是這一類，修法是包成 RPC。

**錢或狀態會錯的（先修這 6 個）：**

| 檔案 | 函式 | 步驟 | 失敗留什麼 |
|---|---|---|---|
| `deposits/page.tsx` | `convertEarnest()` | `deposit_payments.insert` → `deposits.update` ×3 | 訂金轉押金轉到一半：收款有了、押金狀態沒變 |
| `deposits/page.tsx` | `forfeitEarnest()` | `orders.insert` → `deposits.update` | 沒收的收入單建了、訂金還標「未沒收」→ **算兩次** |
| `purchases/page.tsx` | `save()` | 6 步（單、明細刪、明細 upsert、明細 insert、單 update） | 請款單有頭沒明細，或明細對不上總額 |
| `shortterm/page.tsx` | `doMove()` | `orders.update` → `delete` → `insert` | 移房移到一半：舊單刪了新單沒建 |
| `housekeeping/demand-tab.tsx` | `makeRequest()` | `purchase_requests.insert` → `items.insert` → `demand_items.update` | 請款單建了、需求單沒標「已轉」→ 下次再按又一張 |
| `housekeeping/supply-tab.tsx` | `saveCount()` | `supply_count.upsert` → `supply_txn.insert` | 盤點存了、調整那筆沒進 → **餘量從此對不上**而不會叫 |

其餘 11 個是 `update 或 insert`（擇一，不是連續）或已經有手動回滾（`social/addSplit`、`demand-tab/save`），風險低。

**修法**：一個函式一支 RPC（`security definer`，裡面 `raise` 就整批回滾）。`repay_advances()`、`request_leave_batch()` 就是範本。

### 2. `contracts/page.tsx:689` 用 `setTimeout(400)` 等資料庫

```ts
await supabase.from('contracts').update({ end_date }) ...
await new Promise((r) => setTimeout(r, 400));   // ← 等觸發器長出月租單
await supabase.from('orders').update({ amount }).in('order_key', yms);
```

第 618 行還有一個 `500`。觸發器是同一個交易裡跑完才回的，這個等待**沒有意義**；但第三步 `orders.update` **沒接回傳列數** —— 觸發器沒長出單（房號空的契約走前端那條路），這裡就是 update 0 列、畫面說「已展延 N 期」。跟 `hk_day.rooms_override` 那條坑同形狀。

### 3. 121 個 `update / delete` 沒接 `.select('id')`

RLS 擋下來時**回成功、影響 0 列**（CLAUDE.md 第一條坑）。今天 121 處沒接，分佈：`contracts` 14、`admin` 13、`deposits` 8、`social` 7、`shortterm` 7、`demand-tab` 7。不是每一處都會被 RLS 擋，但**沒有一處知道自己有沒有寫進去**。

**修法**：不用一次改完。先改「按下去畫面會變」的那些（樂觀更新）—— 那是使用者會以為成功的地方。

## 🟠 會壞但看得出來

### 4. 錯誤訊息跳在頁面最上方（`flash()`）

10 頁還在用頂部 `flash()`：`admin` 82 處、`deposits` 41、`purchases` 36、`stats-tab` 35、`tax` 32。使用者在畫面下半部操作時看不到，結論是「按鈕壞了」（房務支出半年沒人發現那次就是它）。

**修法**：今天請假表單、暫付明細、其他收支帳抽屜都改成「訊息留在動作旁邊」了 —— 照那個樣子，一頁一頁換。先換 `deposits` 與 `purchases`（錢）。

### 5. `admin/page.tsx:498` `.limit(5000)` 拿不到 5000

Supabase 預設最多回 1000 列，`.limit(5000)` 不會突破它。`orders` 有 5,310 列。這一格只是關帳確認訊息的「會鎖住幾張」，**數字會少報**。註解自己寫著知道 1000 那條，但還是用了 limit。改用 `fetchAll()`（`lib/fetch-all.ts` 已經有）。

### 6. 三頁的 UTC 日期

`toISOString().slice(0, 10)` 是 UTC；台灣凌晨 0～8 點會得到**前一天**。`revenues` 4 處、`contracts` 4 處、`DepositRefundStep` 2、`admin` 2。多半是拿來當「今天」的預設值 —— 凌晨記帳會少一天。`lib/period.ts` 有 `todayStr()`（本地時區），改用它。
