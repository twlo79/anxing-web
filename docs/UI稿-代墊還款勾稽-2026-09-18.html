代墊還款：怎麼自動勾稽

你問的是後半段。先講結論，再講怎麼做。還沒動程式碼。

★ 我的建議是：不要做「自動勾稽」，要讓它「不可能對不起來」。

勾稽的前提是兩份資料各自存在、需要比對。如果愛皮的「實支」是另外存一份， 那它跟安幸的「已收回」就是同一筆錢的兩份紀錄 —— 總有一天會對不起來，而且不會有任何地方報錯（你的 README 上那條： deposits.amount 與 lines 各存一次台幣金額）。

所以：愛皮的實支不存，直接讀那一列暫付的「實收回」算出來。 同一個數字、同一個來源 —— 沒有兩份，就沒有東西要勾稽。

你問的兩個問題

Q1　在哪挑？→ 在安幸的「暫付」頁，不在其他帳本。

理由不是習慣，是錢在哪一側：愛皮還錢 → 錢進安幸的帳戶 → 記帳的動作就該在收到錢的那一側。而且暫付頁本來就有完整的收回流程 （收回日、實收回、進哪個帳戶、驗證），不用重做一套。

★ 其他帳本那一頁是唯讀的結果 —— 它只是把那一列暫付的「實收回」印出來。 這正好強化了「只有一個寫入者」。
★★ 愛皮那一頁會放一條「去暫付頁還款」的連結， 兩邊都進得去，但動作只有一個地方做得了。
Q2　「已付款」是誰付的？→ 是安幸。而那個字現在是錯的。

你一眼就讀成「愛皮已付款」，那不是你看錯 —— 是同一件事在那張表上有三個名字：
欄位名收回日　實收回
狀態已付款　已退款　部分退
三個詞講同一條軸（錢出去 → 錢回來），而 用語表 的規矩是 同一件事只准有一個名字。

改法：狀態全部改用「收回」這個字。
現在改成對代墊來說是對押金來說是
待出款待出款（不變）還沒付給廠商還沒付給房東
已付款待收回安幸付了，等愛皮還押金付了，等退回
已退款已收回愛皮還完了押金退回來了
部分退部分收回愛皮還了一部分被扣了一些
為什麼是「收回」不是加主詞（「安幸已付」）： 那張表每一列的付款方都是安幸（它是安幸的暫付表），所以主詞是多餘的； 而「收回」正好是那兩個欄位已經在用的字。
★ 這會一起改到押金與零用金那幾列的標籤 —— 上面那張表右邊兩欄就是在驗這件事： 三種類別讀起來都通。
★★ 用語表 要加一列：收回（不要用：退款、退回、還款）。

❸ 部分還款怎麼處理？（愛皮只還 5,000，不是 13,209）
  • 讓人挑哪幾筆（建議）　勾起來的那幾列全額收回，沒勾的完全不動。
    每一列不是「已收回」就是「待收回」，沒有中間狀態。三個月後看得懂。
  • 照比例分攤　5,000 按金額比例攤到 8 列，每一列都變「部分收回」。
    代價：8 列全部卡在「部分收回」，而且每一列的零頭都不是真實發生的金額 —— 之後再還一次又要重攤，永遠收不乾淨。
❹ 愛皮那邊的「實支」金額，用哪一個？
  • 實收回（建議）　安幸實際收到多少，愛皮就實支多少。
  • 應支　只要標成已收回就算全額付清。
    代價：如果有短收（愛皮還少了），愛皮的帳上會顯示付清，而安幸那邊短收。

這樣做的代價（要先知道）

愛皮的「實支」變成算出來的，不是存起來的。好處是永遠對得起來，代價有兩個：
  • 其他收支帳那一頁每次要多 join 一張表 —— 資料量小，不是問題
  • 愛皮那邊改不了實支（要改就去安幸的暫付改）。 ★ 這其實是好事：一個地方改，兩邊一起變。
