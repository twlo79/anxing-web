圖 2　一張單的狀態

狀態是每一列自己的。同批三列平常一起走，只有「剔除某一天」會讓其中一列自己走掉。

待主管核→ 待總經理核→ 已核可→ 扣額度 ・ 進日曆 ・ 進出勤表
任一關駁回 待核→已駁回 整批一起退，理由必填，不扣額度
剔除某一天 同批其他列 已核可 ＋ 被剔那一列 已駁回 申請人不用重送
員工自己取消 待核→已取消 整批一起；核完的不能取消
★ 這四個狀態就是現在的四個（pending / approved / rejected / cancelled）， 一個新狀態都沒有加。「剔除一天」在資料庫裡就是「同批裡那一列走 rejected」—— 所以核可流程、通知、稽核全部沿用，不用新語意。

一個交易
資料庫裡（leave_requests，同一個 batch_id）

年假　8 小時　同批 2/3 9/29 09:00 → 18:00

切段規則：連續工作日 ＋ 同一種單位 算一列。
9/29 與 9/30 雖然連著，但一個整天一個半天，所以分兩列。
為什麼不是一列（甲）：一列 9/24 09:00 → 9/30 18:00 會跨過中秋與教師節， 而 attendance_report 只問「這天在不在區間內」—— 中秋節會被印成「年假（特休）」，出勤日曆、月結表、匯出的 Excel 三個地方都會這樣寫。
順便，leave_no_overlap 會把那六天整段鎖住，中間插不進任何單。
為什麼不是一列＋子表（丙）：表達力最好，但要新增一張表（＋ RLS ＋ policy）， 還要改 leave_hours_on、attendance_report， 以及把 leave_no_overlap 從 tstzrange 改成逐日 —— 那是目前唯一在擋「同一天請兩次假」的東西，改壞了不會報錯， 只會變成有人請了兩次假而沒有人發現。

順便修掉的那個 bug
  • 現在的時數是 結束 − 開始 的牆上時鐘時數。 9/24 09:00 → 9/30 18:00 會被算成 153 小時 —— 午休、晚上、週末、中秋、教師節全部算進特休。年假總共 56 小時，所以這張單會被擋下來說「不夠」。
  • 單天之所以看起來正常（你截圖那筆 9/2 09:30→17:30 ＝ 8 小時），是因為使用者自己手動避開了午休。
  • 改成「每天填多少就扣多少」之後，這個減法整個消失。
要你回的
  • 流程對不對？特別是 ⑦「剔除某一天 ＝ 只駁回那一列，申請人不用重送」—— 也可以做成「剔除就整張退回，請他重送」，講一聲。
  • 午休幾點到幾點？ 設定裡只存「上班 09:00、下班 18:00、每日 8 小時」，午休沒有存。 我暫用上午 09:00–13:00、下午 14:00–18:00。 要精確就得在「管理」頁加一個欄位 —— 不加也能跑，只有「指定時數」跨午休時會差一小時。
